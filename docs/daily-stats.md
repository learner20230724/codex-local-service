# 每日调用统计与网页并发

本机已通过 3 路、5 路真实调用及统计重启验证，当前网页上限为 5；数据见[验收记录](concurrency-validation.md)。

所有通过现有本机推理入口的、通过认证的 Chat Completions / Responses 请求都会统一计数。按 **Asia/Shanghai（北京时间）的请求开始日期** 分组，在请求正常结束、失败或断开时更新本机汇总文件；服务正常重启后继续累计。统计从功能启用时开始，不根据之前的内存计数虚构历史。

```sh
codex-proxyctl stats                 # 今天
codex-proxyctl stats 7               # 最近 7 天
codex-proxyctl stats 2026-09-20       # 指定日期
codex-proxyctl stats 7 --json         # 机器可读数据
codex-proxyctl concurrency           # 当前网页上限和活跃数
codex-proxyctl concurrency 3         # 改为 3 路，立即生效
codex-proxyctl concurrency 5         # 改为 5 路，立即生效
```

仍使用原来的密钥和入口。查询接口为 `GET /stats?days=7`，或 `GET /stats?date=2026-09-20`；days 范围 1～366。与推理接口一样需要本机 Bearer 鉴权、拒绝 Origin，不另开端口或公网页面。只查询统计、健康状态及修改开关不计入模型调用。

## 计数方式

- 每个客户端 HTTP 推理请求计一次，分为成功、失败、取消。流式接口即便 HTTP 为 200，未成功完成也不会算成功。
- 按最终选用的网页、Codex 或尚未路由分组。网页失败后由 Codex 完成，计一次 Codex 请求、一次回退；不会算成两次客户端请求。`web_attempts` 另外记录实际向私有网页推理接口提交的次数。
- `fallbacks` 对应带有回退原因的 Codex 请求，包括网页忙、冷却、不支持的网页参数、明确指定其他原生模型等情况。强制 Codex 不计回退。
- 正常完成的实际用量累计在 `reported_tokens`。Codex 没有返回用量而由原有兼容层估算时，也会归到 `estimated_tokens`，不会当作实际用量。
- 网页当前不提供精确 Token 用量，因此按可见输入全文和最终输出文本做轻量估算，单独累计在 `estimated_tokens`。估算按中日韩文字和其他字符给予不同权重，并考虑空白分词；它不是模型官方分词器，可能明显偏离实际值，**不包含隐藏思考、缓存命中、上游额外系统提示词等消耗**。
- 未取得用量的请求记入 `unknown_usage_requests`，不是零消耗。失败的网页尝试即使随后回退成功，其上游消耗也可能未知；汇总用量以最终响应可取得的数据为准，不能用来推算账号剩余额度或官方账单。

实报和估算的输入、输出分列，避免混为一个精确总数。JSON 中还分别保留缓存输入和思考输出用量；它们是输入/输出的子集，不能再次相加。估算中的这些额外字段为未估算的零占位，不代表模型没有思考或缓存。

## 存储与维护

本机文件为 `/var/lib/codex-proxy/stats/daily.json`，目录 0700、文件 0600，由主服务身份写入。每个结束的请求原子更新，只保存按天的数字汇总，**不记录提示词、回答、请求头、Cookie、账号信息或 API 密钥**。异常停机时尚未结束的请求不会补记。

普通安装由 `scripts/serve.py` 启用持久化；独立运行上游 Node 服务时可设置 `CODEX_PROXY_STATS_FILE`。未配置文件则只在内存中统计，查询会明确标记 `persistence=memory`。文件读取损坏时保留原文件，查询返回 `stats_load_failed`；写入失败报告 `stats_write_failed`，不会影响正常推理。故障期间内存计数不应视为已持久保存。

此文件不进入 Git，也不会上传到任何平台。可以直接备份数字汇总文件；不要将私有账号目录作为统计备份。

## 网页并发

HTTP 通道允许 1～5 路，配置为共享 `routing.json` 中的 `web_concurrency`。主网关和私有 HTTP 桥接读取同一配置；调整无需重启。降低上限时让已有请求完成，只限制新请求。每个请求独享 Python 工作进程、HTTP 会话、临时聊天和流订阅，复用同一账号的只读凭据。

超过网页上限的 auto 请求继续使用原生 Codex；原生 Codex 池仍为 2，并没有同时把它放大。强制 web 请求在槽位满时返回 `web_busy`。旧 browser 传输仍只有 1 路，以私有桥接实际能力为限。

一条请求取消只释放自己的槽位，不会清除其他请求的占用，也不会导致所有请求进入冷却。平台限流或其他上游错误仍触发原有冷却；同时完成的成功请求不能抹掉较新的限流状态。提高本机并发不会增加账号额度，也不保证平台始终允许相同并发。
